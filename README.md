# huangguo_flutter

Flutter 短剧浏览、在线播放与下载管理应用。

## 手势解锁

iOS 显示名称为 `Flutter Demo`。在真实应用「设置 → 手势解锁」开启，
依次设置并二次确认 A、B；A 进入真实应用，B 进入交互演示页，两者必须不同。
修改两套手势或关闭开关前均需验证当前 A。设置中退出或切后台不会保存未完成的手势。

- 九宫格点位按从左到右、从上到下编号 1～9，至少连接 4 个不同的点；
  跨过未选择的中间点时自动补入，`1→4→7→8→9` 为大 L。
- 开关默认关闭。启用后，启动、锁屏或切后台再返回都重新验证，不记忆上一次
  进入真实页还是演示页；先输入 B，切后台回来仍可输入 A。
- 解锁层覆盖整个导航器，首次 A 验证前不创建真实页面。真实页锁定时暂停播放，
  iOS 使用原生遮罩覆盖最近任务截图。已有下载任务不会因锁定而删除或取消。
- 凭据以随机盐与 PBKDF2-HMAC-SHA256 派生值保存到系统安全存储，不保存明文手势，
  不加入业务数据迁移。读取失败保持入口锁定，可点击重试。
- 不提供绕过 A 的找回入口；请记住 A。手势入口不对已有业务文件实施加密。
  iOS Keychain 中的设置可能在卸载后保留，重新安装不保证重置。

## 首页状态与收藏

- 首页卡片左上角的星标可收藏或取消，点击星标不会进入详情；详情页也可操作。
  首页「我的收藏」展示本地收藏列表，点击卡片进入详情，取消最后一项后显示空态。
- 任意一集实际播放并产生正进度后，该剧标记「看过」，封面和标题淡化；
  这表示曾观看，不代表整部看完。在线和本地播放共用状态，未播放、零进度、
  暂停跳转或缓冲不会单独触发标记，下载与收藏图标不会随封面淡化。
- 绿色勾「有下载」表示至少一集已完成下载且存在本地资源，不表示整部下载完成。
  下载完成或在 App 中删除后自动更新，首页在 App 返回前台时重新检查资源。
- 已下载列表按集淡化并标记「看过」，专辑显示「看过 X / 已下载 Y 集」；
  本地播放器的选集列表同样展示观看状态，正在选择的剧集仍保留橙色高亮。
- `LibraryService` / `LibraryStorage` 将收藏元数据和按剧、按集的长期观看状态
  保存到应用文档目录的 `library.json`，使用串行写入和临时文件替换。
  启动时从现存播放历史回填正进度记录；之后不受最近 50 条历史上限、清空历史、
  取消收藏或删除下载影响。已被淘汰的旧历史无法回填，缺少剧 ID 的旧记录按剧名兼容。
- 读取损坏文件时不覆盖原文件，保存失败会记录错误，收藏操作也会提示未可靠保存。

## 播放器

在线播放和下载播放统一使用 `lib/widgets/app_video_player.dart`。
页面负责解析地址、创建与释放 `VideoPlayerController`，公共组件负责手势、
控制栏、全屏路由和屏幕方向；全屏切集通过共享状态更新，不重新进出全屏。

- 单击画面显示或隐藏控制栏；播放时 3 秒无操作自动隐藏，暂停时保持显示。
- 双击画面或点击全屏按钮进入横屏全屏；返回后恢复竖屏。
- 左右滑动预览目标时间，松手执行一次跳转；一屏最多调整 120 秒。
- 拖动进度条显示时间预览，结束后恢复拖动前的播放或暂停状态。
- 播放时长按临时使用 2 倍速，松开、取消或进入后台时恢复原倍速。
- 全屏快速上滑下一集、下滑上一集；内嵌模式保留页面纵向滚动。
- 支持倍速选择、缓冲进度、播放错误重试；离线播完停留，可点击播放重播。
- 手动选择的倍速在线/本地共用，切集、重试和重启 App 后恢复；长按临时固定 2×，松开恢复原倍速，不覆盖记忆值，手机端进入加速时轻震一次。
- 设置页的「离开播放页时暂停」默认开启，关闭可在 App 内切页继续播放；系统后台始终暂停，返回不自动恢复，全屏切换和菜单不触发离页暂停。
- 本地播放优先暂停在线播放，即使在线播放仍在加载也不会随后抢播；退出本地播放不会自动恢复在线声音。

历史进度只在进入对应剧集时恢复，手动或自动切集从头播放。
当前预览为时间预览，尚未实现视频缩略帧；保留在线 HLS、
本地视频文件和本地 HTTP 服务播放离线 HLS 的原有路径。

## 下载存储统计

- 「下载管理 → 已完成」底部固定显示设备总空间、设备已用和可点击的 App 占用估算值，
  空列表和搜索时也保留；每套资源的「更多」菜单显示本套已下载文件总大小，
  不受搜索筛选集数影响。
- iOS、Android 统计应用本体与可读取的应用数据、缓存；macOS 沙盒构建也包含
  应用本体，其他环境只统计能读取的应用专属目录并标为「App 数据占用」。
  数值按文件逻辑大小估算，与系统设置的磁盘分配、共享及系统管理数据口径可能不同。
  设备容量对应应用所在存储卷，不包含其他外接存储卷。
- 源文件与转换后的 MP4 同时存在时均计入，同一路径不重复计算，不跟随符号链接。
  设备容量和专辑资源在进入已完成页、返回前台时刷新，下载变化合并后刷新，
  页面可见时每 20 秒更新设备容量和专辑大小，也可点击刷新按钮。
  每次进入已完成页或返回前台时额外统计一次 App 占用，首次显示「统计中…」，
  不随 20 秒定时器重复全量扫描；部分结果明确标注，统计失败保留上次成功值。
- 点击「App 占用」进入独立的「App 空间管理」页；进入或手动刷新时
  在后台 isolate 执行全量扫描，显示等待状态，可随时返回。部分文件无法读取时保留
  可读取部分的估算值，提示统计不完整并列出失败路径；失败时支持重试。
  管理页统计结果同步到已下载页，避免返回后仍显示旧值。
  此页面为后续大文件列表和 MP4 压缩保留入口，本次暂未实现这些操作。
- MP4 转换前记录本集播放列表及其引用分片、密钥的总字节数和分片数；成功后记录
  MP4 大小、增减字节数、百分比及体积倍数。日志包含剧名和集名，批量转换在删除源文件前
  完成对比；复用已有 MP4 时明确记录跳过转换，统计失败不会中断转换。

## 压缩测试

- 「设置 → 压缩测试」先选择已下载的剧名与集数，默认测试开头约 30 秒，
  也可切换「完整一集」。片段模式对比同一段原片与压缩片的大小和画质，
  不将片段体积视为整集体积；切换范围清除旧结果并重置预览。
- 同时展示当前组件可用的软件和硬件编码方案，并使用当前素材试编码验证；
  不因硬件可用而隐藏软件高压缩方案。Mac / iPhone 的 VideoToolbox 硬件方案
  禁止静默回退到软件；缺失或试编码失败的编码器会显示不可用说明。
- x265 提供三个目标体积档位，均使用 `medium` 两遍平均码率编码：
  「强力压缩 · 25%」保留分辨率和帧率、AAC 96 kbps；
  「激进压缩 · 15%」短边最高 720p、最高 30 fps、AAC 64 kbps；
  「极限压缩 · 10%」短边最高 540p、最高 24 fps、AAC 48 kbps。
  缩放保持比例并取偶数尺寸，不放大分辨率或提高帧率；后两档会损失画质及运动流畅度。
- 目标大小按所选范围的原资源字节数计算，扣除音频并预留 3% 封装预算；
  视频预算不足 64 kbps 时明确拒绝。结果显示目标偏差，超出 ±10% 标为未达标，
  不承诺任意素材都能精确达到目标。600 MB 原片三档预算分别约为 150 / 90 / 60 MB；
  30 秒测试结果只代表片段，整集仍需单独验证。
- 保留「清晰优先」「体积优先」作对照：软件 H.264 / H.265 使用 `medium` CRF，
  硬件两档按源视频码率设置预算；这些方案保留分辨率、帧率并复制音轨。
  AV1 优先使用 SVT-AV1（`preset 6 / CRF 36、40`），没有时使用内置的
  libaom-av1（`cpu-used 6 / CRF 36、40 / row-mt / 4 线程`）；
  两者都没有时显示不可用说明，设备播放器可能不支持 AV1 预览。
- 每次测试结果分别保留，可选择历史结果预览对比，显示编码参数、分辨率、帧率、
  原资源大小、新文件大小、节省比例及耗时；体积增加时如实显示。
  原视频和压缩视频共用播放器，切换时保留播放位置，支持全屏对比，不记录观看进度。
- 压缩进度从 0% 开始，显示已处理时长、总时长、处理速度、已耗时和预计剩余时间。
  显式启用周期状态报告，结合统计回调与 FFmpeg 状态日志更新；
  封装和校验显示独立状态，校验成功后保留「100% 完成」。估计所需数据不足时
  显示等待说明，不生成虚假的进度或剩余时间。
  两遍编码按累计处理时长显示进度及当前遍数，第一遍结束不会显示 100%；
  成功、失败和取消后均清理两遍编码统计文件。
- 所选 MP4 或 m3u8 引用的分片、密钥先复制到专属临时目录，
  HLS 在目录内合并为预览 MP4；原资源大小按引用文件去重统计。
  HLS 专用输入选项仅用于 m3u8，不传给 MP4 片段截取；失败时显示处理阶段和 FFmpeg 诊断。
  不替换下载原片、不修改下载记录。切集清除上一轮文件；
  返回时取消当前处理、释放预览并删除本次目录，下次进入清理异常退出的残留目录。

### 视频压缩的思考与阶段结论（2026-11-08）

本轮起点是 WebRecorder 中约 600 MB 视频选择「高压缩」后仍有约 300 MB，
希望在可接受画质下进一步降低存储体积，同时尽量缩短等待时间。
本次在 huangguo 的独立测试入口做对照实验，暂不将这些参数接入正式下载压缩流程。

- **先看实际编码路径，不能只看档位名称。**WebRecorder 的浏览器路径中，
  「高压缩」使用 CRF 28；Electron 原生路径则优先按分辨率计算目标码率，
  例如 1080p 约为 3200 kbps，此时 CRF 不生效。其参数读取中的
  `.find(...)?.next` 也取不到后一个参数，preset 会回退到默认值；
  因此单凭「高压缩」标签和文件缩减比例，无法判断编码器是否发挥了预期效果。
- **CRF 与目标体积解决的是不同问题。**CRF 用于探索画质与体积的平衡，
  文件大小随素材变化；明确要求 150 / 90 / 60 MB 时，应由目标字节数、
  时长和音频开销计算视频码率，再用两遍编码分配预算。两遍编码并不保证画质，
  也不能保证文件精确等于预算；本轮以 ±10% 为体积达标范围。
- **更小的体积有实际代价。**只换 H.265 或 AV1，无法保证任意素材在清晰度不变时
  再缩小几倍；激进方案还会减少分辨率、帧率及音频码率。
  硬件编码优先解决速度问题，软件编码的收益需要同时比较画质、体积和等待时间。
  不能把“压得更小”直接当成“方案更好”。
- **借鉴公开编码思路，按本地能力落地。**本轮参考的方向包括按内容分配码率、
  选择分辨率、分阶段产出以及质量评估；这些不是本项目已经实现的平台级能力。
  当前实现是固定档位与两遍编码，尚未实现按镜头自适应编码、自动画质搜索或 VMAF
  评估，也没有复现 B 站、抖音的完整转码体系。
- **以应用内置组件为准。**系统 FFmpeg 可用的编码器不代表应用内置库也可用；
  本机内置库实测有 x265 和 libaom-av1，没有 SVT-AV1，因此为 AV1 增加 libaom 回退。
  编码支持与播放器解码支持分别验证，不能仅凭编码器列表宣称整条流程可用。
  期间还修复了 MP4 片段截取误用 HLS 专用输入选项而导致的处理失败。

在 macOS 应用中，同一段约 30.1 秒、1280×720 的真实剧集片段实测如下。
下表使用页面显示值，结果只代表该片段和当时设备，不能外推整集压缩率或处理时间。

| 方案 | 原片段大小 | 压缩后大小 | 节省空间 | 输出规格 | 编码耗时 |
| --- | --- | --- | --- | --- | --- |
| 激进压缩 · 15% | 11.32 MB | 1.68 MB | 85.2% | 1280×720、30 fps | 25 秒 |
| 极限压缩 · 10% | 11.32 MB | 1.12 MB | 90.1% | 960×540、24 fps | 17 秒 |

两档体积偏差分别约为 -1.1% 和 -1.2%，均符合本轮体积验收条件；
10% 档在应用播放器中验证过解码和定位到中间画面。
自动化测试另外使用合成素材验证编码、输出规格和完整解码；
这些检查不代替人工检查细节、字幕、运动画面和音画同步。

**阶段结论：体积目标已经跑通，但用户认为综合效果仍不理想，当前暂时接受并保留测试入口。**
这不是最终推荐的生产参数，也不代表原始约 600 MB 视频已完成整片验收。
后续若继续优化，应选取对话、快速运动、暗场和字幕片段，记录同一素材各档位的
体积、画质和耗时，先确定可接受质量下限，再决定是否采用更慢的编码或按场景调整参数；
不能继续仅靠提高压缩强度追求更小数字。

## 验证

```sh
flutter analyze --no-pub --no-fatal-infos
flutter test --no-pub
flutter build ios --debug --no-codesign --no-pub
```

本机安装包含 x265 的 FFmpeg 和 ffprobe 后，可额外执行真实编码冒烟测试；
该测试生成带音轨的合成素材，验证 MP4 片段截取、三档两遍编码和可用的两档 AV1，
再检查输出并完整解码：

```sh
RUN_COMPRESSION_FFMPEG_SMOKE=1 flutter test --no-pub test/compression_ffmpeg_smoke_test.dart
```

播放器测试覆盖控制栏显隐、进度拖动、取消手势、临时倍速恢复、
全屏源更新及窄屏布局。实际解码、网络片源与真机旋转仍需在设备上验收。

本机 Xcode 27 要求部署版本至少为 iOS 15。Runner 已设为 iOS 15，
`ios/Podfile` 同时将依赖的低版本部署目标提升至 iOS 15。
可使用以下命令编译或导出开发签名 IPA：

```sh
xcodebuild -workspace ios/Runner.xcworkspace -scheme Runner \
  -configuration Debug -sdk iphoneos -destination 'generic/platform=iOS' \
  CODE_SIGNING_ALLOWED=NO IPHONEOS_DEPLOYMENT_TARGET=15.0 build
flutter build ipa --release --export-method development --no-pub
```
